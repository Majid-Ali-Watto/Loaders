# circle-loader

A dependency-free JavaScript loading spinner (50 circular variants) published to npm as `circle-loader`. Framework-agnostic: the same API is used from React, Vue, Angular, Svelte, Next.js, Nuxt and plain `<script>` tags.

## Commands

```bash
npm test            # builds first, then runs node --test test/*.test.js (jsdom)
npm run build       # cleans dist/, runs Rollup, writes types/*.d.mts
npm run demo        # builds, serves demo/ and dist/ at http://localhost:5173/demo/
npm run docs:svgs   # builds, regenerates docs/variants/*.svg (README previews)
```

Tests run against `dist/`, not `src/`, so `npm test` always rebuilds. Each test file runs in its own process: `loader.test.js` (full bundle), `core.test.js` (core + variants imported one by one), `configure.test.js` (global config), `features.test.js` (zIndex, progress, blockInput, nonce, shared state), `element.test.js` (the custom element).

## Layout

- `src/core.js`: the `Loader` class, option resolution, CSS injection, variant registry, the default `circle` variant. Entry `circle-loader/core`.
- `src/variants.js`: one named export per variant (`{ name, css, spans?, build? }`) plus `allVariants`. Entry `circle-loader/variants`.
- `src/index.js`: registers `allVariants` and re-exports `Loader`. Entry `circle-loader` (built as `dist/bundle.*`).
- `src/element.js`: the `<circle-loader>` custom element (defined on import, so it has side effects) on top of `index.js`. Entry `circle-loader/element`.
- `rollup.config.mjs` (Rollup 4, `.mjs` because the package isn't `"type": "module"`): the four entries as CJS/ESM, plus CDN IIFEs: `circle-loader.min.js` (all), `circle-loader.element.min.js`, `circle-loader.core.min.js`, and `dist/variants/<name>.min.js` (one per variant, registers with the `CircleLoader` global; the list is read from `variants.js` exports).
- `src/styles/core.css`: overlay, text, backgrounds, `circle`, reduced motion. `src/styles/variants/<name>.css`: one file per variant.
- `types/*.d.ts`: hand-written types. `*.d.mts` copies are generated by `scripts/copy-types.js` and gitignored.
- `demo/index.html`: the public playground (single file, no build). `scripts/demo.js` serves it. It has a light/dark page theme (see Demo below).
- `docs/variants/*.svg`: generated previews (`scripts/variant-svgs.js`). Not published to npm.
- Published files are whitelisted in `package.json` `files`: `dist`, `types`, `README.md`.

## How it works

- **Option layers:** built-in defaults < `Loader.configure()` defaults < named preset < the call's options (`resolveOptions` in core.js). `undefined` means "not set"; `null` means "use the built-in default". The three `loading*Styles` objects merge key by key.
- **Shared state:** registry, instances, defaults, presets and inert counts live in one object on `globalThis[Symbol.for("circle-loader.state")]`, created lazily by `getState()`, so two copies of the package on a page share it. Never keep these in module variables.
- **Instances:** one per target, keyed by element (`null` = fullscreen). `start()`/`close()` are counted; a second `start()` on an open target only updates text.
- **blockInput** (default on): when shown, the overlay's siblings (body's children, or the target's) get `inert`, counted per element in the shared state; elements the page made inert are skipped. Focus is restored on close.
- **CSS:** never injected at import. `injectCss` adds core CSS on first show and each variant's CSS on its first show, at the **top** of `<head>` so users' CSS wins on equal specificity. Each `<style>` gets the `nonce` option, or the nonce of a `<script nonce>` on the page (CSP).
- **Style options** (`color`, `size`, `thickness`...) are set as CSS variables on the overlay (`--circle-loader-*`). The package CSS never sets these variables; defaults live only in `var()` fallbacks.
- **SSR:** every method returns early without `document` (`hasDOM()`); `configure()` needs no DOM.

## Adding a variant

1. `src/styles/variants/<name>.css`. Use the doubled selector `.loading-spinner.loading-spinner--<name>` for the spinner element (it must beat the base `circle` rules), `var(--circle-loader-color, #3b82f6)`, `var(--circle-loader-secondary-color, ...)`, `var(--circle-loader-track, ...)`, `var(--circle-loader-thickness, Npx)`, sizes relative to `var(--circle-loader-size, 50px)`, and wrap **every** duration and delay as `calc(Xs / var(--circle-loader-speed, 1))`. Prefix keyframes `circle-loader-`. Animate only `transform`, `translate`/`scale`/`rotate` and `opacity`: anything else (height, top, border-width, background-position) runs on the main thread and freezes while the page is busy, which is exactly when a loader shows. For a sliding pattern, slide a wider `::before` instead (see `stripes.css`). `arc`, `breathe` and `donut` still break this rule because their look needs it.
2. `src/variants.js`: import the CSS, export the object (`spans` for `<span>` children), add it to `allVariants` (order = display order).
3. Types: the `LoaderVariant` union in `types/core.d.ts`, an export in `types/variants.d.ts`.
4. Tests: the expected map in `test/loader.test.js`, the `allVariants` length in `test/core.test.js`.
5. README: the variants table, plus the `secondaryColor` / `thickness` / `trackColor` / moving-parts tables if it uses them. Demo: `INFO` and `USES` in `demo/index.html`.
6. `npm run docs:svgs`, then check it visually (see below).

## Gotchas (each one has bitten this repo)

- **Changing the shape of the shared state:** bump `STATE_VERSION` in core.js, or an older copy of the package on the same page reads a shape it doesn't know.
- **The CSS minifier rewrites `0%` as `0`**, which makes a `@property` with `syntax: "<percentage>"` invalid, so the browser drops it silently. Use `<number>` and `calc(var(--x) * 1%)` (see `donut.css`).
- **Inline `<script>` in `demo/index.html`:** a literal `</script>` inside a JS string ends the script element. Write `<\/script>`.
- **Keep `variants.js` side-effect free** (plain object exports, no calls at module level) or tree-shaking breaks. Only `dist/bundle.*` and `dist/circle-loader.min.js` are listed in `sideEffects`.
- **ESM output must stay `.mjs`:** the package has no `"type": "module"`, and older Node versions crash on ESM in `.js`.
- **Vue `<script setup>` top-level code runs on the server and again in the browser.** Never put `Loader.start()` there in examples.
- **Nuxt fires `page:finish` without `page:start` on first load,** so plugins must close only what they opened (the README plugin uses a flag).
- **jsdom limits:** `getComputedStyle(el).position` returns `""` (core treats it as `static`), and computed styles don't cascade like a browser.
- **Headless Chrome `--dump-dom` doesn't advance CSS animations,** so computed animated values read as frame 0. Verify animations with `--screenshot` (pause with `animation-play-state` and negative `animation-delay` for a stable frame).
- **Killing processes:** `pkill -f <pattern>` also matches the shell running it. Use background commands with `timeout` instead.

## Verifying UI changes

Unit tests can't see visuals. For CSS, variant or demo changes, render in headless Chrome:

```bash
google-chrome --headless=new --disable-gpu --no-sandbox --user-data-dir=<tmp> \
  --window-size=1280,900 --virtual-time-budget=1500 --screenshot=<out.png> "file://$PWD/demo/index.html"
```

The demo loads `../dist/circle-loader.min.js` (cache-busted) and falls back to `unpkg.com/circle-loader@^1.1.0`, so build first.

## Demo

- **Theme:** page colors are CSS tokens on `:root`. The dark values are written twice, under `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }` and under `:root[data-theme="dark"]`: change both together. The header toggle (`#theme-toggle`) sets `data-theme` on `<html>`, saves it in `localStorage` (`circle-loader-demo-theme`, wrapped in try/catch), and sets `data-dark` for the icon. A small script at the top of `<head>` applies the saved theme before first paint. The toggle code runs before the package loads, so it works even when loading fails.
- **The preview stage stays dark** whatever the page theme: it shows the loader's real default `background: "dark"`. Don't tie it to the page theme.
- **Variant info:** `INFO` (one-line description) and `USES` (which variants use `secondaryColor`, `thickness`, `trackColor`) drive the tiles and grey out unused controls.

## Conventions

- Tabs for indentation, double quotes in JS.
- User-facing warnings use `console.warn("[circle-loader] ...")` and never throw.
- Keep README, types, tests and the demo in step with any API change. New options also need the README options table and, if settable, `SETTABLE` in core.js.
- The demo is public (users are sent there): keep it working from `file://`, through `npm run demo`, and from the CDN fallback.
